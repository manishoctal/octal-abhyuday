# Deploying to Render

This app is a single always-on Node service with a SQLite database on a persistent
disk. It is **not** serverless — run it as one Render Web Service (do not scale to
multiple instances; the DB file and realtime stream live in that one process).

## One-time setup

1. Push this repo to GitHub/GitLab.
2. In Render: **New → Blueprint**, pick this repo. Render reads `render.yaml` and
   creates the web service with a 1 GB persistent disk mounted at `/var/data`.
3. Review the env vars (already defined in `render.yaml`):
   - `DATA_DIR=/var/data` — where `vote.db` lives (the persistent disk)
   - `ADMIN_EMAILS` — comma-separated admin emails
   - `OTP_CODE` — currently `1234`
   - `ALLOWED_EMAIL_DOMAIN=octalsoftware.com`
   - `JWT_SECRET` — auto-generated by Render
4. Click **Apply**. First build runs `pnpm install && pnpm build`, then `pnpm start`.

## Load the employee list (first deploy only)

The persistent disk starts empty, so the candidate pool is empty after the first
deploy. Open the service's **Shell** tab in Render and run:

```bash
pnpm tsx scripts/import-employees.ts
```

This reads `data/employees.csv` (committed in the repo) and writes the 108
candidates into the database on the persistent disk. To refresh the list later,
update the CSV, redeploy, and run the same command (it replaces all candidates).

## Notes

- **Photos** are served from CloudFront (`abhyuday-2026/<empCode>.png`); missing
  photos fall back to generated avatars automatically. No files to upload.
- **Backups**: download `/var/data/vote.db` from the Shell tab anytime, or before
  the finale, as a safety copy.
- **Realtime**: Render keeps SSE connections open by default — nothing to configure.
- Verified for 100–200 concurrent users on the `starter` plan; bump to `standard`
  for extra headroom.
